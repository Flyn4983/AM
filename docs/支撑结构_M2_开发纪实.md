**核心定位**：支撑被显式建模为一个与零件同栅格的占位/符号场 `SupportStructure`，
而非事后贴标签。两档求解器共享同一契约：
- `support_auto`：秒级、几何规则（悬垂角阈值）自动布点。**默认链**走它。
- `support_simulate`：**复用** `asbuilt_plastic` 的逐层生死单元弹塑性 FEM 内核，
  把 `geometry ∪ support` 合并求解，再按零件遮罩回 `AsBuiltPart`——支撑以
  「额外约束 + 散热边界」角色真实降低变形/残余应力。

---

## 1. 目标

商业软件（Simufact / ANSYS / 3DXpert）的标配能力，也是原 STAGES 缺 `support`
阶段时 SLM 变形/失败预测的最大缺口。把"支撑"建模为：

- **符号场** `SupportStructure`：与零件同栅格的支撑占位掩膜 + 元数据（类型 block/overhang、
  悬垂角阈值、足迹 2D/3D 掩膜、统计摘要）。
- **生成**：给定 `PartGeometry`，按规则自动判定需支撑区域，秒级产出。
- **仿真**：高保真档把支撑与零件合并，真实热-力耦合，量化"加了支撑后变形降多少"。

---

## 2. 实现要点

### 2.1 代理默认档 `support_auto`
- 输入 `PartGeometry` + `params={"kind": "block"/"overhang", "overhang_angle_deg": 45.0}`。
- 算法：每列零件最低 z（`_column_bottom`）→ 该列若悬垂（与上方零件无连续支撑）则布支撑
  到基板；`block` 整足迹块支撑，`overhang` 仅悬垂下方支撑。
- 输出 `SupportStructure`（`summary()` 打印体积/覆盖列数/类型）。
- `cost=1.0`，`Pipeline.auto` 默认会选到（除非被更高保真档竞争）。

### 2.2 高保真档 `support_simulate`
- 复用 `amforge.asbuilt_plastic.solve_asbuilt_plastic` 的逐层弹塑性生死单元 FEM。
- 流程：`geometry ∪ support` → 合并几何 → 逐层沉积求解 → 按零件区域遮罩回 `AsBuiltPart`。
- 支撑以「额外约束 + 散热边界」角色进来，物理上降低零件变形/残余应力。
- `cost=50.0`，**默认不选**（见 §3 选路纪律）；需 `select={'support':'support.simulate'}` 显式切换。
- `params={"material": "316L", "max_layers": 12}` 可截断层数控制代价。

### 2.3 契约与注册
- `contracts.SupportStructure`（`core/contracts.py:909`）：占位场 + 元数据，纯数据结构。
- `register_solver("support.auto", "SupportStructure", ("geometry",), fn=support_auto, cost=1.0)`。
- `register_solver("support.simulate", "AsBuiltPart", ("geometry","support","process"), fn=support_simulate, cost=50.0)`。
- forge_adapter 镜像两条路由（`_native_cost` 取单一事实源 cost，防发散）。

### 2.4 GUI 面板
- `gui/preproc.py:293 generate_support(part, kind=...)`：前处理入口，返回
  `support` / `support_mask_2d`（沿 z 投影足迹）/ `support_mask_3d`。
- `gui/preproc_app.py`：2D 切片视图叠加蓝色半透明支撑足迹预览（仅几何级代理默认档）。

## 3. 选路纪律（与 B 档 vof 同理的档位机制）

**`support.simulate` 也是 select-only**——与 `meltpool.vof_flow3d` 同一设计哲学：
高保真档默认不启用，需 `select` 显式切换。理由一致：
- 默认链走最便宜的数值方法，保证开箱可用、显存友好。
- 高保真档代价高（cost=50，复用逐层 FEM），不应被默认auto误选。
- 路由双计数坑（见 MEMORY.md 架构事实）：共享子图重复累加会虚高廉价档代价、反选沉重档 → e2e OOM。已修。

**语义澄清（重要，避免误读）**："select-only" **不是没实现、不是质量差**，
而是"高保真档位需用户明示选择"。`support_auto`/`support_simulate` 都是真实数值方法，
非解析近似、非 stub。

## 5. 存在问题与遗漏点（务必知悉）

1. **`support_auto` 仅几何规则，无拓扑优化**：悬垂角阈值法的支撑体积偏大、
   未做最小支撑/晶格填充等优化；商用软件的"按需支撑"还有距离。
2. **`support_simulate` 复用 asbuilt 内核、层数截断**：`max_layers` 默认小值，
   全零件全层仿真代价可能很高；与 asbuilt 共用生死单元 FEM，其自身局限（见 asbuilt 纪实）会传导。
3. **GUI 仅 2D 足迹预览**：蓝色半透明叠加是几何级代理默认档产物，
   无支撑 3D 几何渲染、无高保真档变形云图对比视图。
4. **无实验/商用软件对照**：与 §3.6（B 档无实验对照）同理，验证为自洽数值，
   未做 Simufact/3DXpert 基准对比。
5. **支撑与铺粉/熔池的耦合尚未全闭环**：`SupportStructure` 可作为额外输入喂铺粉/热-力，
   但"支撑→铺粉可行性→熔池"的端到端 DAG 边仅立项、未全验证（蓝图 DAG 边已留）。
6. **`support.simulate` 与 `meltpool.vof_flow3d` 同时 select 时的代价组合未压测**：
   二者都是高保真档，叠加后显存/时长未系统性回归（详见 B 档纪实 §3.7 硬件待 #38）。

## 6. 后续开发建议

- 把 `support_auto` 升级为"按需支撑"（基于热-力敏感性而非纯几何）。
- `support.simulate` 默认 `max_layers` 调参，或做降阶（ROM）支撑变形估计。
- GUI 补 3D 支撑几何 + 高保真档变形对比视图。
- 压测 `support.simulate + meltpool.vof_flow3d` 组合在 Ubuntu 48G GPU 上的可行性（#38）。
- 补 Simufact/3DXpert 支撑体积/变形基准对照（若获许可数据）。
