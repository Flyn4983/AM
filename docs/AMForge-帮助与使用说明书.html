AMForge · 端到端可微分增材制造仿真平台

帮助与使用说明书 · 版本 0.1.0 · 面向使用者（工程师 / 研究者 / 二次开发者）

一句话定位：AMForge 把「工艺 → 熔池 → 组织 → 本构 → 结构 → 服役判定」整条增材制造（AM）物理链建成一串 纯函数， 既能像 Flow3D 那样正向做高保真熔池 / 热力模拟，也能对整条链求梯度，反向优化工艺参数乃至神经网络权重。 底层数值核心由同仓库的 diffmech（JAX 可微分计算力学：FEM/FVM/DEM/SPH/MPM/相场/CPFE）提供， 通用引擎 forgecore 负责按数据契约自动布线、可替换、可扩展。

本手册能帮你做到三件事：

  1. 看懂：用一章讲清工程背景、物理理论与代码实现思路，快速建立整体心智模型。
  2. 上手：分别用「命令 / 代码（二次开发）/ GUI」三种路径，从零搭出一个仿真模型并跑出结果。
  3. 深入：给出 API 速查、自定义求解器、积木式建模与可微反演示例，支撑二次开发与科研复现。
阅读建议：首次使用直接跳到 第 6 章（命令） 或 第 8 章（GUI） 跑通第一个例子；想照着跑完整案例看 第 10 章教程；想理解原理看第 2、3 章；查 API 看 第 11 章；用对约定看 第 12 章；要写插件 / 科研复现看第 7、11 章。

2. 工程背景

2.1 什么是增材制造（AM）

增材制造（俗称 3D 打印，本平台聚焦 SLM 选区激光熔融 与 LSF 激光送粉）通过逐层铺设粉末、用高功率激光按扫描路径选择性熔融， 把三维 CAD 模型「长」成实体零件。与减材制造相比，它几乎不受拓扑复杂度限制，可制造点阵、随形冷却流道等「传统工艺做不出」的构件。 代价是：热-力过程极端剧烈且跨多尺度，缺陷（翘曲、残余应力、未熔合、孔隙、裂纹）极易产生。

2.2 为什么需要仿真

AM 过程横跨多个物理尺度与时间尺度：

尺度典型长度典型现象数值方法
熔池10⁻⁴ ~ 10⁻³ mMarangoni 对流、汽化、匙孔VOF/CFD（FVM）
零件热历程10⁻³ ~ 10⁻² m逐层热循环、相变潜热焓法热传导（FVM/FEM）
微观组织10⁻⁶ ~ 10⁻⁵ m晶粒生长、枝晶、相变相场 / 统计代理
本构—各向异性、硬化CPFE 均质化
结构/服役10⁻² ~ 10⁻¹ m翘曲、残余应力、强度热-力耦合 FEM / MBD
粉末尺度10⁻⁵ m铺粉密实度、飞溅、球化DEM / SPH / MPM

实验试错成本高、可观测性差（熔池内部无法直接测量）。仿真能在「试打印前」预测变形与缺陷、优化扫描策略与工艺窗口，是 AM 走向「首件即合格」的关键。

2.3 本平台的物理链与「无缝链接」

AMForge 把上述物理串成一条数据契约驱动的前向链：

geometry → process → meltpool → thermal → microstructure
         → constitutive → asbuilt → structural → verdict
                          ↘ powder.bed （粉末尺度缺陷）

每个环节只声明「吃什么契约、吐什么契约」。编排器据此自动布线，换求解器只改一行 select，调用代码不动—— 这正是「无缝链接」的含义，也是构建可维护、可扩展仿真系统的核心设计。

2.4 仿真 ≠ 解析近似

设计原则（用户明确要求）：本平台的「仿真」一律指真实数值方法（FEM/FVM/MPM/SPH/DEM 等离散计算）， 不使用闭式/解析解（如 Rosenthal 解析温度场）作为默认「模拟」求解器。 默认热链路已接真实焓法相变（糊状区有效扩散 + SSP-RK2 时间积分，数值求解并包含潜热）； thermal.history 为降阶代理（仅教学/快速回归用）。

3. 理论模型与代码实现思路

本章按「物理链顺序」逐环节给出原理与关键实现位置，便于你理解代码与做二次开发。公式只点到为止，重点在「用什么方法、落在哪个模块」。

3.1 几何：SDF 体素化

原理：任意几何统一表示为有符号距离场（SDF）的体素栅格。好处：① SDF 是标量场，几何本身可作优化变量（可微）； ② 单一栅格贯穿分层、路径、生死单元激活、几何偏差比较，避免跨网格插值误差；③ 内部孔洞/薄壁/点阵一视同仁。

实现：amforge.geometry 复用 diffmech.methods.am.geometry：from_sdf_fn（解析式基元+CSG 布尔）、from_stl/from_mesh（最近点距离+广义绕数定号）、 from_occupancy/from_density（CT/拓扑优化场）、gyroid/schwarz_p/bcc_lattice（点阵）。AM 诊断：overhang_field/thin_wall_field/printability_report。

3.2 扫描路径

原理：按层切片得到二维区域，用光栅（hatch）填充 + 轮廓（contour）环绕，可用之字形、螺旋等策略。 路径是热载荷的时空分布来源。

实现：diffmech.methods.am.scan_paths：zigzag_hatch / contour_hatch / spiral_hatch / from_csv / from_gcode；GUI 前处理 generate_hatch_paths 直接生成。

3.3 热学：焓法相变热传导（高保真）

原理：固-液共存（糊状区）的相变潜热用焓法（enthalpy method）处理：以焓 H 为未知量，有效扩散系数在固/液/糊状区连续过渡， 潜热自然进入能量方程；时间推进用 SSP-RK2（强稳定保辛 Runge-Kutta）。相比「表观热容法」更稳，比 Rosenthal 解析更真实。

实现：amforge.thermal_enthalpy.solve_enthalpy_thermal（注册为 thermal.enthalpy）；底层 FVM 见 diffmech.methods.fvm.thermal（diffusion_rhs/step_thermal_scan/gaussian_heat_source/moving_gaussian_source）。

3.4 微观组织：相场凝固 vs 统计代理

方法原理位置
相场（高保真）用序参量方程（Allen-Cahn / Karma-Rappel 各向异性）数值求解枝晶/晶粒生长，物理真实amforge.phasefield / diffmech.methods.phase_field
统计代理（默认）由冷却速率/温度梯度经验映射晶粒尺寸、相分数（~免费、全可微）amforge.micro.solve_microstructure

3.5 本构：CPFE 均质化

原理：晶体塑性有限元（CPFE）在每个积分点用滑移系本构描述单晶塑性，经 voigt/reuss 上采样得到各向异性宏观本构场（含 Hall-Petch 细晶强化）。

实现：amforge.constitutive.solve_constitutive（均质化）；内核 diffmech.methods.cpfe（solve_cpfe/qp_state_at_cell/average_equivalent_plastic_strain）。

3.6 成形：逐层激活热-力耦合

原理：按分层高度给单元赋予「激活时间」，未激活单元不计入刚度矩阵（生死单元）；激光热载荷叠加热应变，得到逐层累积的位移/残余应力。

实现：amforge.buildup.solve_buildup（ROM 趋势，默认）；asbuilt.thermomechanical_plastic 走 CPFE 生死单元弹塑性收缩/翘曲（高保真，经 inverse.simulate(asbuilt_solver="plastic") 触发）。 内核：diffmech.methods.am.activation（LayeredMesh/assign_activation_times）、thermomechanical.py（solve_thermomechanical/assemble_activated_stiffness）。

3.7 粉末尺度：DEM / SPH / MPM

原理：铺粉用离散元法（DEM）求颗粒接触力与重力沉降，得密实度/配位数/表面粗糙度；球化用光滑粒子流体动力学（SPH）；剥蚀/飞溅用物质点法（MPM）。

实现：内核 diffmech.methods.dem / .sph / .mpm；AM 封装 diffmech.methods.am.powder_bed（synth_powder_bed 抖动晶格+对数正态 PSD；recoat_dem 铺粉）；amforge.powder.py（ParticleCollection 导入/导出/统计/DEM 求解）、amforge.powderbed.py（powder.bed，按 powder_fidelity 选 surrogate/dem/sph/mpm）。

3.8 数字样机：MBD + FEM

原理：零件本体用 FEM 保证强度/残余应力精度；周边机构用多体动力学（MBD）保证运动/接触效率，二者经协同接口（FEM 子模型边界位移 ↔ MBD 关节载荷）耦合。

实现：amforge.digitaltwin.solve_digital_twin（ROM）；amforge.mbd + diffmech FEM 装配评估。

3.9 可微与逆问题

原理：因为整条链是 JAX 纯函数，jax.grad 可穿透全图，对「工艺向量 z、几何形变场 u、甚至 NN 权重」求梯度，最小化 loss = 尺寸偏差 + 残余应力 + 缺陷罚项。

实现：amforge.inverse：simulate（正向可微闭环）、predict_process（NN 几何→工艺）、optimize_*（形状/工艺/几何-工艺优化）、optax 反传。Pipeline.function() 把整链柯里化成 f(params, **inputs)，直接喂 jax.grad。

3.10 多目标优化：为什么用 NSGA-II

加权求和 L(λ)=λ·尺寸偏差+(1-λ)·残余应力 只能覆盖 Pareto 前沿的凸包，会系统性漏掉非凸段上的真实最优解。 pareto_optimize_geometry_process(algorithm="nsga2") 在联合设计空间（形状场 u，工艺向量 z∈[0,1]⁹）上做真 NSGA-II 进化（非支配排序+拥挤度），恢复真实（凸/非凸皆可）前沿。旧 "lambda" 路径保留作回归对照。

4. 整体架构

4.1 三包关系

消费关系：amforge 直接 from diffmech... 调用内核；amforge 通过 forge_adapter 把求解器镜像进 forgecore；forgecore 不反向依赖 amforge（仅惰性 import amforge.forge_adapter）。

4.2 数据契约（contracts）

9 个 frozen dataclass 契约是唯一通信语言：PartGeometry, ProcessPlan, ThermalHistory, MeltPoolResult, MicrostructureResult, ConstitutiveField, AsBuiltPart, StructuralResult, ServiceVerdict（另有 PowderBedResult）。所有求解器输入/输出都是这些契约，单位统一 SI。换求解器不会破坏上下游。

4.3 双注册表与镜像

amforge.core.registryforgecore.registry.REGISTRY
类型模块级字典 _SOLVERS（静态，不参与 JAX 追踪）SolverRegistry 类 + 全局实例（两索引 _by_name/_by_produces）
消费方amforge.core.graph.Pipeline 自动布线（活路径）forgecore SimulationModel.build / REGISTRY.auto
注册@register_solverREGISTRY.register_fn(...)

两套表 各自独立、各自活跃（不是「靠覆盖侥幸」）。forge_adapter.register_am_solvers() 在导入时把 amforge 求解器镜像进 forgecore（含统一 cost 单一事实源），使两个引擎都能用同一组求解器。

4.4 编排：Pipeline.auto 自动布线

Pipeline.auto(target, modality, select, given, require_differentiable) 从目标契约反向链式搜索最小代价路径（带记忆化的 DFS），求解器优先于适配器、按 cost 排序保证可复现。结果是一个静态拓扑序 Pipeline（不含张量），可安全被 jax.jit 捕获。

  • .describe() / .mermaid()：人可读 / Mermaid 流程图，可贴进报告。
  • .run(geometry=...)：正向执行，返回 {槽名: 契约}。

def loss(params):
    ab = f(params, geometry=geo)

@register_solver(
    "process.my_rule",

    differentiable=True, cost=1.0,

def my_process(*, geometry: PartGeometry, params=None) -> ProcessPlan:

11.1 顶层与编排 API（amforge）

Pipeline（自动布线）

af.Pipeline.auto(target, *, given=("PartGeometry",), modality=None,
                 select=None, exclude=(), require_differentiable=False,
                 use_adapters=True, name="") -> Pipeline
  • target：契约类名或槽名，如 "AsBuiltPart" / "ServiceVerdict" / "verdict"。按它反向推导最小代价求解路径。
  • select={环节: 求解器id}：强制某环节走指定求解器（如 {"thermal":"thermal.enthalpy"} 切高保真）。
  • 返回 frozen Pipeline，含拓扑序 steps；纯函数，可进 jax.jit。

run 的 params 为嵌套 dict {求解器id: {参数}}；高层 inv.simulate 接受扁平 params。两者不要混用（见 12.3 参数格式约定）。

12. 使用规范

把项目用对、用好，需要遵守下面几条约定。部分是强制的（精度、参数格式），部分是推荐最佳实践（保真度、二次开发）。与 教程 / API 配套阅读。

12.1 环境与精度（强制）

  • 运行前必须置 PYTHONPATH=src 与 JAX_ENABLE_X64=1（见 第 5 章）。不开启 x64 会出现 NaN / Inf 或被吞掉的精度损失。
  • 使用 amsim 虚拟环境（已装 jax 0.11 + pytest）。default 环境无 jax，不可用。
  • 受限环境装 GUI 依赖前先 export PYTHONPATH= BASH_ENV= 中和 safe-delete 拦截层，再用国内镜像源安装。

12.2 保真度选择（默认 vs 高保真）

场景配置说明
快速预研 / 可微优化默认（代理模型）快、全可微；绝对精度依赖校准
真实熔池 / 热-力thermal_solver="enthalpy" / asbuilt_solver="plastic" / micro_solver="phasefield"数值方法（FVM / FEM / 相场），含潜热、糊状区
自定义环节Pipeline.auto(..., select={"thermal":"thermal.enthalpy"})按环节强制高保真
设计原则：仿真＝数值方法，不是解析近似。默认链路已是真实数值（焓法相变）；Rosenthal 解析仅作教学 / 快速回归，勿当作默认物理。

12.3 参数格式约定

  • inv.simulate(..., params={...})：扁平 dict，键为参数名（如 record_frames、n_grid），由内部路由。
  • Pipeline.run(..., params={...})：嵌套 dict {求解器id: {参数}}（如 {"thermal.enthalpy": {"record_frames": True}}）。
  • record_frames=True 是动画 / GIF / PVD 的前提（详见 第 9 章）。

12.4 粉末床与粒子规范

  • CSV 导出用 %.17e 保 float64 无损往返（%.9e 会丢精度导致 __eq__ 静默失败）。
  • use_precise=True 将导入坐标作为 DEM 沉降初态；均匀床统计等价，结构化异质点云才保留布局信息。
  • 粉末床参数（d50 / PSD / 层数）按真实统计映射到 powder.bed，避免大零件床被稀释。

12.5 二次开发规范

  • 新增求解器用 @register_solver(name, consumes=, produces=, stage=, cost=, differentiable=) 声明契约；保持纯函数（无副作用），方可被 jax.jit / grad 与自动布线消费。
  • 优先在原生 amforge.core.registry 注册，再经 forge_adapter 镜像进 forgecore；镜像 cost 须从原生 spec 取（单一事实源），避免发散。
  • 每个新增能力配 pytest，守住契约类型与（若可微）梯度有限性。

12.6 GUI 与可视化规范

  • 无显示环境设 QT_QPA_PLATFORM=offscreen；VTK 3D 自动回退 2D 云图，不要强制 Render()（会触发原生段错误）。
  • GUI 测试须隔离跑（同进程多 Qt+VTK 窗口触发段错误），不要与其它 GUI 测试混跑。
  • 大网格性能：先用小 n_grid / 少层快速验证，再放大规模。

12.7 性能与数值规范

  • 可微优化学习率保守（optimize_shape 默认 0.01）；真实焓法下 0.05 首步过冲发散。
  • 形状场为全网格体素，纯进化收敛慢；生产级建议对 u 用降维基（Zernike / 随机傅里叶），或开启 seed_with_lambda 梯度种子引导。

13.2 能力边界（诚实声明）

  • 算法正确性：NSGA-II 与整链可微性有回归测试守住。
  • 工程保真度：默认链路为代理模型，绝对精度依赖你切换的高保真求解器与校准材料参数；框架本身不「免费」给出工业级定量精度，需配合标定使用。
  • 样本效率：形状场 u 为全网格体素，纯进化收敛较慢。生产级前沿建议：对 u 用降维基（Zernike / 随机傅里叶），或开启 seed_with_lambda 用梯度种子引导。
  • 平台：已在 Windows + 管理 Python 3.13 验证；Ubuntu + 48G GPU 全保真回归（#38）待硬件到位。
