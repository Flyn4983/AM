AMForge 功能扩展架构集成蓝图

在现有「求解器即模块 + DAG 自动布线 + 双注册表镜像 + 原生可微」架构上，补齐 支撑结构 / 二次工艺 / 材料标定 / 监测闭环 四大能力。

规划基线：源码实测 amforge.core.registry（STAGES / SolverSpec / AdapterSpec）、forge_adapter.py 镜像机制、contracts.py 11 契约、inverse 优化内核、digitaltwin.rom。所有方案均落到真实扩展点，非凭空设计。

0. 现状接入点（规划依据）

四个新模块都遵循同一套已验证的扩展机制，无需改动编排内核（amforge.core.graph.Pipeline 按 consumes/produces 契约自动反推依赖并布线）。

机制现状（实测）新模块如何利用
STAGES 11 阶段 + utility：geometry → process → powderbed → meltpool → thermal → microstructure → constitutive → buildup → assembly → structural → verdict 新增 support、postprocess、monitor 三阶段；calibration 不进流水线（离线工具）
SolverSpec 字段 name, consumes(tuple), produces, stage, modality, differentiable, cost, defaults, doc 每个新求解器均显式声明 differentiable/cost/modality
注册装饰器 @register_solver(...) / @register_adapter(...)，自动 DAG 布线 + 签名校验 新能力一律登记为 SolverSpec/AdapterSpec
双注册表 amforge.core.registry._SOLVERS（被 Pipeline 活路径消费）＋ forge_adapter 镜像进 forgecore.registry.REGISTRY 每个新求解器必须在 forge_adapter.py 加一行镜像，否则 forgecore 引擎看不到
契约表 contracts.py 11 契约（PartGeometry…ServiceVerdict），经 SLOT_OF 映射为调用参数名 新增 SupportStructure / SecondaryProcessResult / SensorData / MonitoringState / CalibrationReport，Material 需从字符串升级为契约
可复用资产 inverse 逆问题优化器（jax.grad+L-BFGS/Optax）、digitaltwin.rom（实时结构响应）、asbuilt.thermomechanical_plastic（塑性热-力耦合）、diffmech.postprocess（ParaView 导出） 标定复用 inverse 优化内核；监测复用 digitaltwin.rom；支撑/二次工艺复用 asbuilt 热-力耦合
关键约束：① 求解器必须是纯函数（给定 params+输入契约→输出契约），不得依赖全局可变状态或张量值 Python 分支；② 用户硬约束「仿真=真实数值方法、须配误差报告」——任何高保真/标定求解器都须配套 CalibrationReport；③ 多候选按 cost 选路，高保真须 select= 显式启用，默认链路不 OOM。

1. 总体集成原则（四条）

原则1 一切皆契约 + 求解器：新能力一律登记为 SolverSpec / AdapterSpec，吃/吐现有或新增契约，复用自动 DAG 布线，不写硬编码串联。

原则2 双注册表镜像：新求解器在 forge_adapter.py 加一行镜像（cost 用 _native_cost(name, default) 单一事实源取，防字面量漂移——此前 process.constant/thermal.enthalpy 已踩过坑）。

原则3 默认代理 / 显式高保真：沿用 process.heuristic 思路做规则代理（秒级、可微、默认走）；高保真档（如 thermal.enthalpy）须 select= 显式启用，默认链路不 OOM。

原则4 误差报告优先于新物理：任何"真实物理"求解器（尤其标定与高保真）必须输出 CalibrationReport/验证套件，否则不宣称"可用"——这是从研究原型迈向可信工程软件的门槛。

2. 模块A · 支撑结构生成与仿真

商业软件（Simufact/ANSYS/3DXpert）的标配；当前 STAGES 无 support 阶段，是 SLM 变形/失败预测的最大缺口。

2.1 接入点

  • 新增 STAGES 阶段 "support"（位置：geometry 之后、powderbed 之前）。
  • 新增契约 SupportStructure（contracts.py）：support_sdf/mask (ndarray)、kind (str: block/line/cone/skin)、contact_area (f32)、volume_fraction (f32)、params。

2.2 求解器（遵循 register_solver 统一签名）

# src/amforge/support.py

    doc="悬垂角阈值规则自动布点支撑")

    ...  # 返回 SupportStructure

@register_solver("support.simulate",
    consumes=("PartGeometry","SupportStructure","ProcessPlan"),
    produces="AsBuiltPart", stage="support", modality=("SLM",),
    cost=50.0, differentiable=True,
    doc="把支撑 occupancy 并入逐层热-力耦合")
def support_simulate(*, geometry, support, process, params):
    # 复用 asbuilt.thermomechanical_plastic 的逐层激活，
    # 追加 support.mask 为约束/散热边界
    ...

2.3 DAG 边与复用

  • geometry → support.auto → SupportStructure
  • geometry + SupportStructure → powderbed（支撑区也铺粉）
  • SupportStructure + AsBuiltPart → support.simulate（修正成形）
  • 复用：asbuilt.thermomechanical_plastic 的塑性热-力耦合内核，仅增加 occupancy/边界输入。

2.4 双注册表镜像 & GUI

  • forge_adapter.py 加镜像：support.auto（代理默认）、support.simulate（高保真，select={'support':'support.simulate'}）。
  • GUI 前处理标签页加「生成支撑」按钮 + 类型/密度滑杆 + 预览（复用现有几何云图）。
两档策略：代理=support.auto（秒级、默认）；高保真=support.simulate（显式启用，需实验标定后宣称可用）。

3. 模块B · 二次工艺仿真（热处理 / HIP / 切削）

Simufact 标配；对残余应力重分布、孔隙闭合、最终尺寸影响巨大，目前链路在 buildup/structural 后直接断到 verdict，缺中间再处理。

3.1 接入点

  • 新增 STAGES 阶段 "postprocess"（位置：structural 之后、verdict 之前）。
  • 新增契约 SecondaryProcessResult：包裹 AsBuiltPart + treatment (str: HT/HIP/machining) + residual_relief_factor + density_after + geometry_after。

3.2 求解器

# src/amforge/postprocess_secondary.py
@register_solver("postprocess.heat_treatment",
    consumes=("AsBuiltPart",), produces="SecondaryProcessResult",
    stage="postprocess", cost=5.0, differentiable=True,
    doc="闭式应力松弛+再结晶（残余应力按温度/时间衰减，可微）")
def ht_relax(*, asbuilt, params): ...

@register_solver("postprocess.hip",
    consumes=("AsBuiltPart",), produces="SecondaryProcessResult",
    stage="postprocess", cost=5.0, differentiable=True,
    doc="孔隙闭合：密度场→~1.0")
def hip_densify(*, asbuilt, params): ...

@register_solver("postprocess.machining",
    consumes=("AsBuiltPart","PartGeometry"), produces="SecondaryProcessResult",
    stage="postprocess", cost=2.0, differentiable=False,
    doc="余料去除 + 最终形位偏差，喂给 verdict")
def subtractive(*, asbuilt, geometry, params): ...

3.3 DAG 边与复用

  • buildup / structural → postprocess.* → verdict（verdict.service 现有 consumes=(structural, asbuilt, constitutive) 追加 secondary）。
  • 复用：直接站在 asbuilt 产出之上；HT 应力模型复用 constitutive 弹塑性参数。
forge_adapter.py 镜像三个求解器；GUI 后处理页加「二次工艺」卡片（选类型、看松弛后残余应力云图）。

4. 模块C · 材料标定（最高优先级 · 最低风险 · 最强可信度杠杆）

不进流水线，是「产线前」离线工具 + CalibrationReport 契约；直接满足用户「实打实真实物理 + 误差报告」硬约束，是把系统从研究原型推向可信工程软件的最快路径。

4.1 接入点

  • 新增契约 Material（集中物性：k, ρ, cp, E, ν, σy, 吸收率 η, 相场参数，目前以字符串 "316L" 传递，应升级为契约对象）。
  • 新增契约 CalibrationReport（误差、parity 数据、置信区间）。
  • 新增子包 amforge.calibration（不参与前向 DAG，产物 Material 经 params['material'] 流入所有求解器）。

4.2 实现（复用 inverse 优化内核）

# src/amforge/calibration/__init__.py
@dataclass
class CalibrationDataset:        # 实验记录
    process: list                 # 工艺参数
    measured: list                # 实测熔池尺寸/残余应力/硬度

def loss(theta, dataset):
    # 优化对象是 Material 参数 theta，而非几何/工艺
    pred = simulate_with_material(theta, dataset.process)  # 复用 thermal/asbuilt 求解器
    return mean((pred - dataset.measured)**2)

def fit(dataset, init_material):
    # 复用 inverse 的 jax.grad + L-BFGS/Optax
    theta_star = optax_lbfgs(loss, init_material.to_theta())
    return Material.from_theta(theta_star), CalibrationReport(dataset, theta_star)

4.3 复用 & 合规

  • 优化内核：inverse.optimize_*（已验证的 jax.grad 梯度闭环）。
  • 被标定黑盒：thermal.enthalpy / asbuilt.thermomechanical_plastic / micro.phasefield。
  • 校验可视化：diffmech.postprocess 出 parity 图。
  • 合规：CalibrationReport 必须含 误差≤X% 实证 + 基准对标（建议 NIST 悬垂件/熔池尺寸公开数据集），否则不宣称高保真求解器可用。
GUI：标定标签页（导入实验 CSV → 跑 fit → 看 parity plot + 误差≤X%）。建议作为 M1 首个落地（投入小、可信度跃升最大）。

5. 模块D · 监测闭环 / 数字孪生闭环（差异化旗舰）

2025 研究前沿核心方向（缺陷率可 18.5%→5.2%）；系统已有 digitaltwin.rom 是最自然落点。

5.1 接入点

  • 新增 STAGES 阶段 "monitor"。
  • 新增契约：SensorData（时序信号：光电/热成像/熔池影像）、MonitoringState（缺陷概率：未熔合/匙孔/孔隙）、ClosedLoopPlan（修正后 ProcessPlan）。

5.2 求解器 / 适配器

# src/amforge/monitoring.py
@register_adapter("RawSensorStream", "SensorData")
def ingest(*, raw, params): ...            # 原始 CSV/流 → SensorData

@register_solver("monitor.detect",
    consumes=("SensorData","ThermalHistory"), produces="MonitoringState",
    stage="monitor", differentiable=False,
    doc="NN/统计分类缺陷指示")
def detect(*, sensor, thermal, params): ...

@register_solver("monitor.correct",
    consumes=("MonitoringState","ProcessPlan"), produces="ProcessPlan",
    stage="monitor", differentiable=False,
    doc="控制器输出修正工艺")
def correct(*, monitor, process, params): ...

5.3 闭环编排层（关键新概念）

  • 闭环不是单求解器，而是外层迭代驱动：amforge.closedloop.run_loop(geo, base_plan, monitor, n_iter) 反复调用 pipe.run，实现 ProcessPlan ⇄ MonitoringState 反馈。
  • 同时可把 SensorData 喂回模块C 做在线重标定（仿真↔监测双向校正）。
  • 复用：digitaltwin.rom（轻量实时结构响应做在线预测）；inverse 优化器（控制器可用梯度/贝叶斯）。
架构决策：现有 Pipeline 是纯前向 DAG，闭环放在外层迭代驱动，不改动 Pipeline 内核，保持 DAG 纯洁。GUI：监测仪表盘标签（传感流回放 + 缺陷图叠加 + 工艺修正记录）。

8. 风险与开放问题

架构风险

  • 闭环需外层迭代驱动：不改 Pipeline 内核（保持 DAG 纯洁），但 run_loop 需管理状态与早停。
  • Material 从字符串升级为契约：需同步改所有 solvers 的 params 取用，影响面较大，建议先加兼容层（字符串仍可用）。

物理可信度风险

  • 支撑/二次工艺的"真实物理"求解器需实验验证，否则仅作代理可用——这与原则4一致。

性能风险

  • HIP/HT 大零件体素策略、闭环实时性需 HPC/多卡——当前无 HPC 故事（呼应前次审视"性能与规模"项）。

开放问题：监测 detect 用 NN 还是统计分类？是否先接公开数据集（如 L-PBF 熔池图像）做离线验证再接实时流？建议先做离线 detect + 静态缺陷图，再迭代到在线闭环。
