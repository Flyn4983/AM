## 1. 架构三层（一句话）

| 层 | 包 | 职责 |
|----|----|------|
| AM 编排 | `amforge` | 纯 JAX 求解器 + registry/forgecore 双注册 + Pipeline + GUI |
| 计算力学库 | `diffmech` | JAX FEM/FVM/DEM/SPH/MPM/相场/CPFE 底层算子 |
| 槽位注册引擎 | `forgecore` | 通用求解器槽位、依赖解析、选路；镜像 amforge 原生注册 |

- 单 wheel；运行前置：`PYTHONPATH=src JAX_ENABLE_X64=1`。
- GUI 分层：纯逻辑层（`*_logic.py`/`preproc.py`/`postproc.py`）+ UI 层（`*_app.py`，PySide6+VTK）。
  offscreen 下跳过 VTK 3D 渲染避免原生段错误（详见 `MEMORY.md` 环境事实）。

## 2. 用户铁律（两句话，任何改动都不得违反）

1. **仿真 = 数值方法**（FEM/FVM/MPM/SPH/DEM 等离散计算），**不得用闭式/解析解**
   （如 Rosenthal 解析温度场）作为默认"模拟"求解器近似处理。
2. **默认链路须全程 `jax.grad` 可微**（JAX 自动微分，不能断链）。

> 用户对"默认链走代理/解析权宜"高度敏感：要求开箱即"实打实"的真实物理模拟。

---

## 3. 选路纪律（默认链如何选求解器）

- registry `SolverSpec` 有 `method` 分类：`numerical` / `analytical` / `proxy`。
- `Pipeline.auto` 默认 `exclude_methods=("analytical",)`，双引擎一致排除闭式/解析 →
  **默认走真实数值**（`meltpool.fdm` 3D FVM 焓法 / `thermal.enthalpy`）。
- **档位机制（关键）**：高保真档（如 `meltpool.vof_flow3d`、`support.simulate`）默认不启用，
  需 `select={"meltpool":"meltpool.vof_flow3d"}` / `select={'support':'support.simulate'}`
  显式切换。这叫 **select-only**。
  - select-only **绝不是"没实现/质量差"**——而是"高保真档位需用户明示选择"。
  - 默认走最便宜的数值方法，保证开箱可用、显存友好。
- ⚠️ **路由双计数坑**：`graph._Planner.resolve` 必须按"每个求解器只计一次"求和 DAG 代价；
  否则共享子图重复累加会虚高廉价档代价、反选沉重档 → e2e OOM（~71GB）。已修。

## 6. 诚实边界速查（跨会话务必牢记）

1. `meltpool.fdm` 是传导 FVM，**无** VOF 自由界面/Marangoni/反冲/匙孔；需高保真用 vof（select-only）。
2. vof 梯度病态，反演前必配 clipping。
3. M4 `monitor.detect` 是物理规则代理占位，非 NN/统计分类。
4. 所有验证均为自洽数值，**无实验/商业软件对照**。GPU 状况已变（2026-10-06 更新）：本机 **RTX A6000 48G** 存在且用户已授权自由使用（此前条目"待硬件"作废）；A5 已实测（开发日志 §25.7），但**全保真零件尺度回归仍未跑**，且 `xla_cuda13` 插件在 GPU 不可见时 `cuInit` 失败会静默回落 CPU——报"GPU 结果"前必须核对日志里的设备清单。
5. `_refs/` 为参考资料（7.1M，未被 import），仅供人工查阅，不进运行时。
6. **热求解器档位（D1 决定，§25.8）**：标定档 = `thermal.enthalpy`（瞬态 + 真实潜热，GPU 实测 82.83 M vox·step/s）；零件尺度的**主线是 D2**（活跃子网格 × 多重网格子循环，仍数值+瞬态），**备胎 D3** = 本征应变 + 可微线弹 FEM 的**数值降阶**（标 `fidelity="reduced"`，须量化与标定档偏差）。两者**均未实现**。⚠ 受用户铁律约束（`.workbuddy/memory/MEMORY.md:4-6`）：**默认链不得走 Rosenthal/Eagar–Tsai 闭式**，闭式只当快速初值/教学档。在 D2/D3 落地前，默认链仍调焓解 ⇒ 零件尺度**算术上不可行**（实测外推 74 天/次正向、NSGA-II 一轮 4.4 年），且 §24.5「越加密越冷、默认配置不熔化」未除根。
7. **f32 不可用于标定输出**（§25.7）：GPU f32 不比 f64 快（dx=25 档 15.34 vs 16.56 M），且 Δpeak 31.07 K、Δvol 4.17%；更要命的是 dx=50 档 f32 的体积 0.0759 ≈ dx=12.5 档 f64 的 0.0745 —— **f32 数值扩散在形态上伪装成"加密网格"**。JAX 对写死 `float64` 的位点只发 UserWarning 并静默截断。
8. **体素化对 dx 的浮点拼写敏感（T1，待修 D4）**：`geometry.py:113-119` 的 `ceil((hi-lo)/spacing)+1` 使 `dx_um*1e-6` 与字面量 `12.5e-6`（差 1 ulp）给出**不同层数**（161602 vs 156849 体素）→ 同零件 peak 差 0.53%、熔体积差 1.77%。跨探针比物理量**必须先比 `sdf.shape`**。
9. **GPU 只在够大的网格上有效**：吞吐随网格单调升（CPU 0.75→1.35→2.40，GPU 0.84→16.56→82.83 M，未见饱和），而 ~1.3 ms/步的启动开销使链条小算例（1000 体素 × 681 步）GPU/CPU = **0.88×**。⇒ GPU 服务标定档的细网格长行程，**不服务**反演循环里的小算例。

## 8. 环境 / 测试速查

- 项目 Python = `amsim` venv（jax 0.11.0 + pytest 9.1.1）。
- 跑测试：`PYTHONPATH=src JAX_ENABLE_X64=1 <amsim>/python -m pytest tests/ -q`
- 单跑子集（建议先跑）：`tests/test_meltpool_vof.py` / `tests/test_support.py` / `tests/test_meltpool_temperature_dependent.py`
- Ubuntu 全量回归 CPU 约 1h+，建议先子集再全量。
- **CUDA 现状（2026-10-06 实测）**：`jax_plugins/xla_cuda13` 已装可用（driver 580.173.02 / CUDA 13.0，RTX A6000 48G），GPU 可见时 `jax.devices()` 返回 `[CpuDevice, CudaDevice]`。⚠ **陷阱**：GPU 被占用/不可见时插件只打印 `CUDA_ERROR_NO_DEVICE … Falling back to cpu` 就继续跑 CPU ⇒ **凡声称"GPU 实测"的日志必须含设备清单行**，否则该数字默认按 CPU 处置。
- GPU 已获授权使用（2026-10-06 起），但**共享纪律不变**：卡上常驻 `newton_torch_env` 计算进程 + 桌面 Xorg，不得抢占、不得终止他人进程，被要求即归还。
- 2026-10-06 会话实测用的解释器 = `/tmp/amvenv/bin/python`（JAX 0.11.0 + x64），与 `amsim` venv 并存；探针一律 `PYTHONPATH=src` 从项目根运行。
- pip 装包前 `export PYTHONPATH= BASH_ENV=` 绕过 safe-delete 拦截（沙箱 fix）。
